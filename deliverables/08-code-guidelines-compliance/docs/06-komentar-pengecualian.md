# 06 - Komentar Pengecualian

Setiap pengecualian yang berada di dalam kode harus memiliki komentar yang
menjelaskan alasan dan batasannya. Komentar tidak boleh sekadar menonaktifkan
aturan tanpa alasan.

## 1. Komentar yang Diterapkan

### EX-05 — Internal helper

File: `src/Inventory.Application/Services/ApprovalGuard.cs`

```csharp
// EX-05: Internal workflow helper. It is intentionally excluded from the public
// API surface and therefore does not require public XML documentation.
internal static class ApprovalGuard
```

Alasan: kelas `internal`, bukan kontrak publik.

### EX-06 — Transisi Web → EF

File: `src/Inventory.Web/Controllers/AppControllerBase.cs`

```csharp
// EX-06: Temporary Web -> EF dependency until Inventory.Api owns
// transaction/concurrency handling (see ADR 006).
if (ex is Microsoft.EntityFrameworkCore.DbUpdateConcurrencyException)
```

Alasan: penanganan `DbUpdateConcurrencyException` masih diperlukan selama Web
masih berbagi proses dengan EF Core. Akan dipindahkan ke client/API.

## 2. Komentar untuk Pengecualian Generated

### EX-01 — EF Migration

Jangan mengedit file migration. Jika perlu anotasi, tulis di file partial atau
dokumentasi, bukan di file generated:

```csharp
// Generated by EF Core. Do not edit manually.
// Changes must be made through a new migration.
```

### EX-02 — DocFX YAML

File `api-metadata/*.yml` adalah output DocFX. Jangan dirapikan manual; ubah
sumber XML comment lalu generate ulang.

## 3. Komentar untuk Razor Nullability

File view dapat memakai null-forgiving jika model sudah divalidasi controller:

```cshtml
@* EX-04: Razor nullable analysis limitation; model validated by controller. *@
@Model.Title!
```

## 4. Komentar untuk SQL

SQL bukan C# dan mengikuti aturan berbeda:

```sql
-- EX-07: PostgreSQL DDL/DML script; C# naming/style rules do not apply.
```

## 5. Aturan Penulisan Komentar

1. Sebutkan ID pengecualian (`EX-*`).
2. Jelaskan alasan teknis.
3. Jelaskan batas/akhir pengecualian.
4. Cantumkan rencana perbaikan bila bersifat sementara.
5. Jangan memakai komentar untuk menyembunyikan error.

## 6. Contoh Komentar yang Dihindari

```csharp
// BAD: no reason
#pragma warning disable
```

```csharp
// BAD: hides failure
catch { }
```
